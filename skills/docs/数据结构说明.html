1.1 位置与文件布局


  • - account = {wxid}_{device}；多账号时取 mtime 最新的一份（decrypt_all.py 逻辑）。
  • - 每个 .db 附带 -shm / -wal（WAL 模式）；镜像需连同主库一起解出逻辑内容。

1.2 加密格式（SQLCipher v4）

参数值
页大小 PAGE4096
保留区 RESERVE80（页尾）
盐 SALT16 字节（文件头前 16 字节）
KDFPBKDF2-HMAC-SHA512(raw_key, salt, 256000, 32)
分组AES-256-CBC，每页独立 IV

页结构：[0:16] 盐 + [16:4016] 密文 + [4016:4032] IV + [4032:4096] 保留。

  • - 第 1 页解密后，替换文件头前 16 字节为 SQLite format 3\0（盐在明文库里让位给标准头）。
  • - 页头校验（key 正确性判据）：解密第 1 页 → pt[0]==0x10, pt[1]==0x00, pt[4]==0x50, pt[5]==0x40, pt[7]==0x20。

全链路三处复用：extract_raw_key.verify_candidate / decrypt_all.decrypt_db / bootstrap.verify_key。

1.4 local_type 打包公式

```

local_type = (subtype << 32) | base_type

文本 = 1

引用消息 = (57 << 32) | 49 = 244813135921

链接分享 = ( 5 << 32) | 49 = 21474836529

```

过滤必须取模：WHERE local_type % 4294967296 = 49（直接 = 49 零命中）。

1.5 发送者链（已证伪的旧假设 vs 正确链）

```

✗ 旧假设: real_sender_id → contact.id → 已证伪(大群抽样分库核对, 零命中)

✓ 正确链: real_sender_id → 所在库 message_N.db 自己的 Name2Id.rowid → wxid

→ contact(remark>nick>alias, 含非好友) / stranger 兜底

→ wxid == db.get_my_wxid() ? "me" : 对方

```

msg0 / msg1 两库 Name2Id 编号各自独立（同一 wxid 在两库 rowid 不同）——必须分库解析，勿跨库套用。

6. 建库后自检清单（不含任何预设规模）

本文档刻意不提供任何绝对规模数字（会话数、消息条数、边数、成员数一律省略）。

原因：规模本身即隐私，且随每个人语料不同而变；写死数字还会让文档随语料增长迅速失效。

正确的核对方式——只查「导出口径」与「库内口径」是否一致，不看绝对量：

```bash

① 导出总量（各会话 messages 之和）

PYTHONUTF8=1 .venv/Scripts/python.exe -c "

import json,glob

n=sum(len(json.load(open(f,encoding='utf-8'))['messages'])

for f in glob.glob('wxlocal/exports21/*.json') if not f.endswith('cards.json'))

print('exports21 messages =', n)"

② 库内消息总量 —— 必须等于 ①

PYTHONUTF8=1 .venv/Scripts/python.exe -c "

import sqlite3

db=sqlite3.connect('wxlocal/wxbase.db')

print('wx_messages =', db.execute('SELECT COUNT(*) FROM wx_messages').fetchone()[0])"

③ 幂等自检：重建前后两次 ② 必须一致

若第二次翻倍 → 说明走了追加而非清空重灌（违反不变量 19）

```

校验项期望关系（比值口径，与规模无关）
wx_messages ↔ exports21/messages 总数相等
含 sq 占比≈ 100%（v2.1 起全量携带）
含 sid 占比接近 100%，仅极少数异常行缺失
含引用 q／含 at 占比个位数～低两位数百分比（随群性质浮动）
wx_edges 内部拆分at + reply + cooccur = 总边数（build_graph.py 跑完后）
重建两次的 ②完全一致（幂等）

记不住数字是对的：任何"这个库应该有 X 条"的硬编码期望都是 bug。

判断健康与否看一致性（① = ②、重建幂等），不看绝对量。

6.1 时间窗与备份

导出窗口（--days N）决定入库范围；窗口取值只影响条目多少，不影响 schema。做对比实验或改变窗口前，
