# 微信语料数据结构说明（wechat-decrypt / wxlocal）

> 版本：v1.0 ｜ 2026-09-26 ｜ 范围：**数据准备链路**（加密库 → 提 key → 解密 → 导出 → 建库）
> 性质：全部字段与规模均**实测**（`wxbase.db` 2026-09-26 全量历史态）；口径与坑逐条标注证据。
> 配套：流程手册见 skill `wechat-data-prep/SKILL.md`；导出格式原始规范见 `docs/wxexport_v2_spec.md`；
> 融合设计见 `docs/fusion-analysis.md`。

---

## 0. 三层数据总览

```
L0 原始加密库            ①提key        ②解密              ④导出              ⑤建库
~/Documents/xwechat_     ────>      decrypted/       ────>  exports21/      ────>  wxlocal/
files/*/db_storage/                 <account>/               wx_*.json              wxbase.db
(SQLCipher v4 加密)                 db_storage/             cards.json             (六表, 明文)
                                    (明文镜像)              membership.json
                                                           manifest21.json
        L0                        →         L1（wxexport/2.1）        →            L2（wxbase.db）
```

| 层 | 载体 | 性质 | 规模（2026-09-26 全量历史） |
|---|---|---|---|
| **L0** | 微信加密库 `db_storage/**/*.db` | SQLCipher v4 密文，随微信运行变化 | message/contact/contact_fts 等 22 个库 |
| **L1** | `wxlocal/exports21/` | 明文 JSON（wxexport/2.1），**脱敏友好**（PII 只在一处花名册） | 每会话一文件 + `cards/membership/manifest` |
| **L2** | `wxlocal/wxbase.db` | SQLite 六表，分析直接消费 | 见 §3 |

**三层各自回答什么**：L0 = 微信真实状态（权威但加密、结构复杂）；L1 = 可移植的中间语料
（跨机交换、云端入库的接口）；L2 = 本机分析库（索引化、口径统一、含派生列）。

## 1. L0 —— 原始加密库（微信 4.x）

### 1.1 位置与文件布局

```
~/Documents/xwechat_files/
└── {wxid}_{device}/                    # account，如 wxid_example_main_xxx
    └── db_storage/
        ├── message/
        │   ├── message_0.db            # 消息库（分库；>N 条后分裂 message_1.db…）
        │   ├── message_1.db
        │   └── ...
        ├── contact/
        │   ├── contact.db              # 联系人
        │   └── contact_fts.db          # 全文/群名片（含 chatroom_member_fts_v3）
        └── ...                         # session/media/其他
```

- `account = {wxid}_{device}`；多账号时取 **mtime 最新**的一份（`decrypt_all.py` 逻辑）。
- 每个 `.db` 附带 `-shm` / `-wal`（WAL 模式）；镜像需连同主库一起解出逻辑内容。

### 1.2 加密格式（SQLCipher v4）

| 参数 | 值 |
|---|---|
| 页大小 PAGE | 4096 |
| 保留区 RESERVE | 80（页尾） |
| 盐 SALT | 16 字节（**文件头前 16 字节**） |
| KDF | `PBKDF2-HMAC-SHA512(raw_key, salt, 256000, 32)` |
| 分组 | AES-256-CBC，每页独立 IV |

**页结构**：`[0:16] 盐` + `[16:4016] 密文` + `[4016:4032] IV` + `[4032:4096] 保留`。
- 第 1 页解密后，**替换文件头前 16 字节为 `SQLite format 3\0`**（盐在明文库里让位给标准头）。
- **页头校验**（key 正确性判据）：解密第 1 页 → `pt[0]==0x10, pt[1]==0x00, pt[4]==0x50, pt[5]==0x40, pt[7]==0x20`。
  全链路三处复用：`extract_raw_key.verify_candidate` / `decrypt_all.decrypt_db` / `bootstrap.verify_key`。

### 1.3 关键表与字段（明文后）

| 表 | 关键列 | 说明 |
|---|---|---|
| `Msg_<md5>` | `create_time` `local_type` `real_sender_id` `sort_seq` `server_id` `message_content` `source` | 每会话一张消息表，表名 = `Msg_` + 会话 wxid 的 md5 |
| `Name2Id` | `rowid` → `user_name` | **发送者链的枢纽**；每个 message_N.db **各有一份** |
| `contact` | `id` `username` `nick_name` `remark` `alias` | 昵称优先级 `remark > nick_name > alias` |
| `stranger` | `username` `nick_name` `remark` | 非好友兜底 |
| `chat_room` | `id` `username` `ext_buffer` | `ext_buffer` = 群名片 PB（wxid→名片→邀请人） |
| `chatroom_member` | `room_id` `member_id` | **真实在群成员**（含从未发言者）；id 指向 `contact.id` |
| `chatroom_member_fts_v3`（在 contact_fts.db） | `room_id` `member_id` `a_group_remark` | **群昵称**来源；其 id 是**该库 name2id 的 rowid**，须转 wxid 再关联 |

**消息列语义**：

| 列 | 类型 | 说明 |
|---|---|---|
| `create_time` | int | **秒级** unix 时间戳（同秒多条靠 `sort_seq` 区分） |
| `sort_seq` | int | 同秒内单调递增排序键（3.3% 相邻消息同秒，此列保真） |
| `server_id` | int | 服务端消息 id（**引用 join 的键**，`q.svrid` 回链它） |
| `real_sender_id` | int | 指向**本库** `Name2Id.rowid`（≠ `contact.id`） |
| `local_type` | int | 类型（打包，见 §1.4） |
| `message_content` | blob | 内容；部分经 **zstd 压缩**（magic `28 b5 2f fd`） |
| `source` | text | XML，含 `<atuserlist>wxid,…</atuserlist>`（**精确 @**） |

### 1.4 `local_type` 打包公式

```
local_type = (subtype << 32) | base_type
  文本     = 1
  引用消息 = (57 << 32) | 49 = 244813135921
  链接分享 = ( 5 << 32) | 49 = 21474836529
```

**过滤必须取模**：`WHERE local_type % 4294967296 = 49`（直接 `= 49` **零命中**）。

### 1.5 发送者链（已证伪的旧假设 vs 正确链）

```
✗ 旧假设: real_sender_id → contact.id          → 已证伪(大群抽样分库核对, 零命中)
✓ 正确链: real_sender_id → 所在库 message_N.db 自己的 Name2Id.rowid → wxid
          → contact(remark>nick>alias, 含非好友) / stranger 兜底
          → wxid == db.get_my_wxid() ? "me" : 对方
```

> **msg0 / msg1 两库 Name2Id 编号各自独立**（同一 wxid 在两库 rowid 不同）——必须**分库解析**，勿跨库套用。

## 2. L1 —— 导出层：wxexport/2.1

每会话一个 `exports21/wx_<slug>.json`；另有三份**跨会话汇总**（cards/membership/manifest）。
相对 wxexport/2 新增 5 个结构化字段（依据 `docs/fusion-analysis.md`），**全部可选、向后兼容**。

### 2.1 文件族

| 文件 | 粒度 | 内容 |
|---|---|---|
| `wx_<slug>.json` | 每会话 | 该会话的 meta + chats（participants + messages） |
| `cards.json` | 跨会话 | `{slug: {room, kind, display, cards:{wxid: 群名片}}}` |
| `membership.json` | 跨会话 | `{slug: {room, kind, display, count, members:[{wxid,name}]}}` |
| `manifest21.json` | 跨会话 | 导出清单 + `summary`（按 kind 汇总，含 `empty` 标记） |

**slug 约定**：群 `wx_<群名净化>`（只保留 `\w` 含 CJK）；私聊 `wx_dm_<wxid净化>`。
库内 `chat_raw` **去掉 `wx_` 前缀**。群名含 emoji 必须净化；slug 撞车追加 wxid 的 md5 前缀。

### 2.2 `meta`

| 字段 | 说明 |
|---|---|
| `schema` | 恒 `"wxexport/2.1"`（v2 为 `"wxexport/2"`） |
| `generated_at` | 导出时刻 |
| `days` / `limit` | 窗口天数 / 每会话上限 |
| `since` / `until` | 显式区间（unix 秒，0 = 不设） |
| `window` | 人读窗口标签；合并后为 `"合并 A + B"` |
| `segments` | （合并时）各段窗口列表 |
| `chats` / `messages` | 会话数 / 总消息数 |
| `fields` | 2.1 新增字段说明（`sq/sid/at/q/kind`） |
| `sender_chain` | 发送者解析链（审计用） |
| `prefix_stripped` | 本次剥离的冗余前缀条数 |
| `merged_from` | （合并时）来源文件 |

### 2.3 `chats[]` 与 `participants`

```json
"chats": [{
  "wxid": "12345678@chatroom",
  "display": "【示例群B】🌟AI×OPC×IP社群",
  "kind": "group",                          // 2.1 新增: group | private
  "count": 3,
  "range": ["<起>", "<止>"],
  "participants": {
    "me": {"name": "我", "wxid": "wxid_example_main", "msgs": 1},
    "p1": {"name": "示例用户A", "wxid": "wxid_example002…", "msgs": 2}
  },
  "messages": [ ... ]
}]
```

- 键空间：`"me"` **保留**给账号主人（**所有 me 账号归并到 `me` 键**）；其余 `p1…pN` 按首次出现顺序。
- `name` 优先级 `remark > nick_name > alias > wxid`。
- **本机版 `me` 也带 `wxid`**（云端 v2 为隐私不带）；本机端到端做 join 对拍需要它。
- `msgs` = 该成员发言行数（不含系统消息）。

### 2.4 `messages[]` 消息行

| 字段 | 类型 | 2.1 新 | 说明 |
|---|---|---|---|
| `t` | int | — | unix **秒**，**升序** |
| `ty` | str | — | 类型标签（文本/图片/语音/链接/撤回/加入群聊…） |
| `s` | str | — | 花名册键：`me` = 我，`pN` = 对方成员 |
| `c` | str | — | 内容文本（系统消息为可读文案）；**入库后保留引用全貌** |
| `sys` | 1 | — | 系统消息标记（仅真时携带，**无 `s`**） |
| `ev` | str | — | 系统事件码（`pat`/`recall`/`group_join`…） |
| `txt` | 1 | — | 纯文本可读标记 |
| **`sq`** | int | ✓ | `sort_seq`，同秒 tie-break |
| **`sid`** | str | ✓ | `server_id`（**字符串**，供 svrid join） |
| **`at`** | str[] | ✓ | `atuserlist` 的精确 wxid 数组（携带率 34%） |
| **`q`** | obj | ✓ | `refermsg` 结构化，见 §2.5 |

### 2.5 `q` —— 引用结构（refermsg）

```json
"q": {"svrid": "1234567890123456789", "by": "示例成员", "wx": "wxid_xxx",
      "ref": "有结果及时通知我…", "room": "12345…@chatroom"}
```

| 键 | 来源 | 说明 |
|---|---|---|
| `svrid` | `refermsg.svrid` | **join 键**；→ 同库 `server_id` 命中 **98.3%** |
| `by` | `displayname` | 被引者显示名 |
| `wx` | `chatusr` | 被引者 wxid（== 真实 wxid 97%） |
| `ref` | `content` | 被引原文（**剥前缀**后截断 120 字） |
| `room` | `fromusr` | 被引消息所在会话 wxid |

> `refermsg` 各字段出现率（微信客户端行为，与语料规模无关）：`type/svrid/fromusr/content` 100%、`displayname` 99%、`chatusr` 95%。

### 2.6 汇总三文件结构

```json
// cards.json
{"demo_group_alpha": {"room": "…@chatroom", "kind": "group", "display": "示例群A",
                "cards": {"wxid_example003": "示例成员-城市-FDE"}}}

// membership.json
{"demo_group_alpha": {"room": "…@chatroom", "kind": "group", "display": "示例群A",
                "count": 429, "members": [{"wxid": "wxid_…", "name": "…"}]}}

// manifest21.json
{"schema": "wxexport/2.1", "days": 0, "limit": 10000000, "mode": "full",
 "scope": "整池", "groups_source": "groups.json:<群数> + dms.json:<私聊数>",
 "window": {"label": "全部历史(不限窗口)", "explicit": false, "since": 0, "until": 0},
 "groups": [{"slug": "demo_group_alpha", "kw": "…@chatroom", "kind": "group", "ok": true,
             "messages": 1398, "empty": false, "new_messages": 1398,
             "participants": 120, "members": 429, "cards": 88, "kb": 512,
             "stripped_prefix": 37, "secs": 0.4}],
 "summary": {"ok": <会话数>, "fail": 0, "empty_chats": <空会话数>,
             "total_messages": <消息总数>, "total_members": <成员行总数>,
             "by_kind": {"group": {...}, "private": {...}}}}
```

### 2.7 v2 → 2.1 演进与验收清单

| 演进 | 内容 |
|---|---|
| 字段 | 消息行 +`sq`/`sid`/`at`/`q`；chat +`kind`；meta +`since/until/window/prefix_stripped` |
| 文件 | 新增 `cards.json`（群名片）、`membership.json`（成员全量） |
| 排序 | SQL 显式 `ORDER BY create_time DESC, sort_seq DESC`（不再依赖隐式扫描序） |
| 兼容 | 新字段全可选 → v2 消费方（wx2corpus v3）读 2.1 行为不变 |

**验收**：`meta.schema` 分流；每文件 `json.load` 成功；`chats[].count == len(messages)`；
`t` 非降序；所有 `s` 都在 `participants`；`me` 键存在；脱敏只动 `participants[].name/wxid`。

## 3. L2 —— 本地分析库 `wxlocal/wxbase.db`（六表）

### 3.1 `wx_messages` —— 消息主表

| 列 | 类型 | 来源（L1） | 说明 |
|---|---|---|---|
| `id` | int PK | — | 自增 |
| `chat_raw` | text | `<slug>` 去 `wx_` | 会话 slug（群 `demo_group_alpha` / 私聊 `dm_example`） |
| `chat_type` | text | `chats[].kind` | `group` \| `private` |
| `sid` | text | `m.sid` | server_id |
| `sq` | int | `m.sq` | sort_seq |
| `sender_full` | text | `participants[s].name` | 花名册全名（`me` → `"我"`） |
| `sender_wxid` | text | `participants[s].wxid` | 花名册 wxid |
| `is_me` | int | `s == "me"` | 1/0 |
| `text` | text | `m.c` | **保留引用全貌**（`[引用消息]… [↩ 群id: 原文]`） |
| `ty` | text | `m.ty` | 类型标签 |
| `at_users` | text | `m.at` 的 JSON | `["wxid_a",…]` |
| `quote_svrid` | text | `m.q.svrid` | 引用目标 server_id |
| `quote_by` | text | `m.q.by` | 被引者显示名 |
| `quote_wx` | text | `m.q.wx` | 被引者 wxid |
| `quote_room` | text | `m.q.room` | 被引消息所在会话 |
| `quote_ref` | text | `m.q.ref` | 被引原文（截断） |
| `ts` | int | `m.t` | unix **秒** |
| `ts_ms` | int | `t × 1000` | 毫秒（排序/展示用） |
| `ts_iso` | text | 由 `t` 格式化 | `YYYY-MM-DDTHH:MM:SS`（本地时区） |

**索引**（14 条，含 9 条 wx_messages）：`sender / ts / chat / sid / qsvrid / chattype /
(chat_raw,ts_ms) / (chat_raw,sender_wxid) / quote_by`。

> **引用段不剥**：入库时 `text` **保留** `[引用消息]评论 [↩ 群id: 原文]` 全貌（供上下文还原
> 与引用边构建）；**只有**算「评论正文」指标（均长/疑问率）才调 `_common.strip_quote()`。

### 3.2 `wx_coref` —— 指称词典（一人多名）

| 列 | 说明 |
|---|---|
| `person` | 归并后的规范名（花名册主名） |
| `alias` | 别名（群名片 / 孪生账号名 / wxid） |
| `alias_type` | `card`（群名片种子）\| `identity`（铁证归并）\| `wxid`（分析层补） |
| `evidence` | 来源证据（如 `chat_room.ext_buffer@demo_group_alpha`、`openim孪生@…`） |
| `UNIQUE(person, alias)` | 去重 |

三类来源：`card`（分析层从 `cards.json` 灌入的群名片）／`wxid`（分析层 `build_graph.py` 追加的 wxid 别名）／
`identity`（`identities.json` 登记的同人账号）。**具体行数随语料而定，不预设期望值**。

### 3.3 `wx_edges` —— 关系边

| 列 | 说明 |
|---|---|
| `src` / `dst` | 两端人名（花名册全名） |
| `etype` | `at`（建库产出）\| `reply` / `cooccur`（分析层 `build_graph.py` 追加） |
| `strength` | 频次 |
| `chat` | 所属会话 |
| `first_ts` / `last_ts` | 首次/末次 |

三类边：`at`（建库时产，来自 `atuserlist`）；`reply`（分析前置 `build_graph.py` 产，`quote_svrid` 精确 join，
命中率高）；`cooccur`（分析前置产，±5 发言位窗）。**建库只产 @ 边，其余归分析前置**（职责分离）。
`strength` 为该边累计次数（被 @ 次数 / 被引用次数 / 共现次数）。

### 3.4 `wx_membership` —— 成员全量（沉默者分母）

| 列 | 说明 |
|---|---|
| `room` | 会话 slug |
| `display` | 会话显示名 |
| `wxid` / `name` | 成员 wxid / 花名册名 |
| `chat_type` | `group` \| `private` |
| `spoke` | 是否在消息表发言过（1/0）——**分母口径关键** |
| `card` | 群名片 |

口径：群按成员快照展开为行，`spoke=0` 即**从未在消息表出现**的成员（沉默者，是真实分母的一部分）；
具体行数与沉默比例**随群而定，不预设**。私聊同样记 1 行（对手方），使分母口径与群一致。
> 注意：沉默率只有「成员快照 ≥ 发言人数」时才可算，否则应标"不可算"而非 0。

### 3.5 `wx_profile_features` —— 特征指纹（分析层）

`person` PK ／ `n_msgs` `avg_len` `emoji_rate` `question_rate` `tech_rate` `peak_hour`
`night_rate` `top_hours`。由分析层 `build_graph.py` 按 `FEAT_MIN_MSGS` 阈值筛选后灌入。

### 3.6 `wx_verify` —— 事实验证登记（分析层）

`entity` `claim` `source_msg_ts` `level`(A/B/C) `status` `evidence` `check_date`。**行数由实际核验条目决定，不预设期望值。**

### 3.7 与云端五表的对齐 / 升级

| 维度 | 云端 social-chat-analysis | 本机 wxbase.db |
|---|---|---|
| 会话范围 | 只有群 | **群 + 私聊**（`chat_type` 区分） |
| 文本纯净度 | 保留存储层 `wxid:` 前缀 | **导出 + 入库双重剥离，残留 0** |
| 引用定位 | 20 字键文本匹配 94–98% | **svrid join 99.8%** |
| @ 识别 | 文本别名匹配（曾炸出大量假边） | **`at_users` 精确 wxid** |
| 沉默者分母 | 只有发言者 | **membership 全量** |
| 身份归并 | 无 | **`identities.json` + openim 孪生自动归并** |

## 4. 字段溯源矩阵（L2 ← L1 ← L0）

| L2 (`wx_messages`) | L1 (`wxexport/2.1`) | L0（加密库 · 明文后） |
|---|---|---|
| `chat_raw` / `chat_type` | 文件名 slug / `chats[].kind` | 会话 wxid（`@chatroom` 判定） |
| `sender_full` / `sender_wxid` | `participants[s].{name,wxid}` | `real_sender_id → Name2Id.rowid → wxid → contact` |
| `is_me` | `s == "me"` | `wxid ∈ me 账号集`（`identities.json`） |
| `text` | `m.c`（剥前缀后） | `message_content`（zstd 解压后，**引文保留**） |
| `ty` | `m.ty` | `local_type % 2³²` 映射 |
| `at_users` | `m.at` | `source` 的 `<atuserlist>` |
| `quote_*` | `m.q.{svrid,by,wx,ref,room}` | `refermsg` 字段 |
| `ts` / `ts_ms` / `ts_iso` | `m.t` | `create_time`（秒） |
| `sq` / `sid` | `m.sq` / `m.sid` | `sort_seq` / `server_id` |

## 6. 建库后自检清单（不含任何预设规模）

**本文档刻意不提供任何绝对规模数字**（会话数、消息条数、边数、成员数一律省略）。
原因：规模本身即隐私，且随每个人语料不同而变；写死数字还会让文档随语料增长迅速失效。

正确的核对方式——**只查「导出口径」与「库内口径」是否一致**，不看绝对量：

```bash
# ① 导出总量（各会话 messages 之和）
PYTHONUTF8=1 .venv/Scripts/python.exe -c "
import json,glob
n=sum(len(json.load(open(f,encoding='utf-8'))['messages'])
      for f in glob.glob('wxlocal/exports21/*.json') if not f.endswith('cards.json'))
print('exports21 messages =', n)"

# ② 库内消息总量 —— 必须等于 ①
PYTHONUTF8=1 .venv/Scripts/python.exe -c "
import sqlite3
db=sqlite3.connect('wxlocal/wxbase.db')
print('wx_messages =', db.execute('SELECT COUNT(*) FROM wx_messages').fetchone()[0])"

# ③ 幂等自检：重建前后两次 ② 必须一致
#    若第二次翻倍 → 说明走了追加而非清空重灌（违反不变量 19）
```

| 校验项 | 期望关系（比值口径，与规模无关） |
|---|---|
| `wx_messages` ↔ `exports21/messages` 总数 | **相等** |
| 含 `sq` 占比 | ≈ 100%（v2.1 起全量携带） |
| 含 `sid` 占比 | 接近 100%，仅极少数异常行缺失 |
| 含引用 `q`／含 `at` 占比 | 个位数～低两位数百分比（随群性质浮动） |
| `wx_edges` 内部拆分 | `at + reply + cooccur` = 总边数（`build_graph.py` 跑完后） |
| 重建两次的 ② | **完全一致**（幂等） |

> 记不住数字是对的：**任何"这个库应该有 X 条"的硬编码期望都是 bug**。
> 判断健康与否看**一致性**（① = ②、重建幂等），不看**绝对量**。
